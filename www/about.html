This is a super lightweight web server written in C.
No frameworks. No magic. Just C, sockets, and HTTP.

─────────── ✦ ⚙ ✦ ───────────

This is implemented using a thread pool and kernel queue. Specifically, I'm using the kqueue API. It's available on MacOS and BSD. There are analogous APIs for pretty much any modern operating system, like epoll on Linux and IOCP on Windows. The kqueue interface allows our process to be notified by the kernel when there is an event on a file descriptor, like incoming connections and available reads. We get to choose what event the kernel monitors for. This is nice because it can make threading much simpler, programmatically speaking. All we need is a thread to look for connections, accept them, and register them for event monitoring. Then we need a thread to handle these notifications, where they are doled off to a thread pool that handles them. This general architecture—event-driven I/O plus a worker pool—is how many modern servers (like nginx or Redis) operate at their core. Here we get to see what that looks like from quite a low level, albeit this is microscopically light-weight as compared with the functionality those frameworks implement.

───+───

The largest efficiency gain in polling for events is that we don't become I/O bound. If worker threads blocked waiting for input, an arbitrary connection could hog bandwidth by sitting idly. kqueue for the win!
